# skilldrift cli: try, install, unlink, remove, list, info


## Problem

Skills live in repos that users clone and edit. There's no lightweight CLI bridge between "skills in a cloned repo" and "skills active in a tool config." Copy-pasting folders or manually symlinking is error-prone and untracked.

## Concept

A minimal CLI that treats `./skills/*` in the cloned repo as the source of truth and offers two ways to activate skills:

- **`try`** — symlink (`ln -s`). Fast, reflects edits in real-time. Good for local development.
- **`install`** — copy. Decoupled from the repo. Good for stable, portable use.

Both write to `~/.config/skilldrift/skills.db` so skilldrift knows what's installed, what's experimental, and where it came from.

## Proposed interface

```
skilldrift try                          # ln -s all skills from ./skills/* (prompts)
skilldrift try SKILL [SKILL ...]        # ln -s specified skills only

skilldrift install                      # cp all skills from ./skills/* (prompts)
skilldrift install SKILL [SKILL ...]    # cp specified skills only

skilldrift unlink SKILL [SKILL ...]     # remove symlink, clean db record
skilldrift remove SKILL [SKILL ...]     # remove copy, clean db record

skilldrift list                          # show all skills, experimental vs installed
skilldrift info SKILL                    # show db record only (name, method, source, timestamp)
```

## Scope

- **In scope:** try, install, unlink, remove, list, info commands; skills.db tracking; reading from `./skills/*`
- **Out of scope:** skill discovery, skill selection, skill registry, anything beyond local repo management

## Key details

| | `try` | `install` |
|---|---|---|
| Method | `ln -s` | `cp -r` |
| Live edits | Yes (symlink) | No (copy) |
| Undo | `unlink` | `remove` |

`~/.config/skilldrift/skills.db` stores: skill name, source path, method (symlink/copy), timestamp.

## Behavior decisions

- **`try`/`install` without args:** prompt for confirmation listing all skills that will be activated before proceeding
- **`list`:** distinguish `experimental` vs `installed` visually (e.g. color, symbol, or column)
- **`info`:** db record only — name, method, source path, timestamp. No SKILL.md parsing.
