# `skills.db` schema and read/write layer with goose migrations


## Context

Part of

- #16

## Problem

Every skilldrift command needs a persistent store to track which skills are
active, how they were activated (symlink vs copy), and where they came from. 

I propose a schema and a Go read/write layer backed by SQLite, versioned via goose
migrations.

## Schema

Single `skills` table in `~/.config/skilldrift/skills.db`:

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER | Primary Key |
| `name` | TEXT | Skill directory name |
| `method` | TEXT | `'symlink'` for `try`, `'copy'` for `install` |
| `source` | TEXT | Absolute path the symlink points to / copy originated from |
| `created_at` | INTEGER | Unix timestamp of when the skill was activated |

## Migrations

Managed with [goose](https://github.com/pressly/goose) (v3). Migrations are
written as `.go` migration files.

## Go read/write layer

A `db` package with: `Open` (open DB + run migrations), `Insert`, `Delete`, `Get`, `List`.

`Open` also creates `~/.config/skilldrift/` if it doesn't exist.

## Acceptance criteria

- [ ] Goose dependency added (`github.com/pressly/goose/v3`)
- [ ] Initial migration creating the `skills` table
- [ ] `db` package with `Open`, `Insert`, `Delete`, `Get`, `List`
- [ ] Auto-migrate on startup
- [ ] Tests for all db operations

## Out of scope

- Wiring `db` calls into CLI commands (separate issues)
