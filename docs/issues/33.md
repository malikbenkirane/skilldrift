# writing-plans: issue-linked plan naming (`issue-<NN>` infix)

Source: user request (2026-11-26). Plans addressing a filed issue are currently indistinguishable by name from any other plan — the `docs/plans/<DATETIME>_<fitted_name>.md` naming carries no pointer back to the issue that motivated it, so locating "the plan that fixed issue N" requires reading file contents.

## Problem

`skills/writing-plans/SKILL.md` § Plan Save Location defines a single naming pattern: `docs/plans/<slug-name>.md` (or `docs/plans/<DATETIME>_<TITLE>/` directories for split plans). There is no convention for when the user asks for a plan that addresses a specific issue in `docs/issues/NN.md`.

Consequences:

- Retrieval by issue number is impossible without opening/grepping every plan file.
- The issue number is a stable, already-current identifier in this repo (all of `docs/issues/NN.md` follows it); plans should key off it instead of inventing a second linkage scheme.
- A plan may drift from its fitted name over time, but the issue number never does.

## Desired behavior

When the plan task comes from (or mentions) a specific issue `NN` in `docs/issues/`:

- Single-file plans: `docs/plans/<DATETIME>_issue-<NN>_<fitted_name>.md`
- Split plans (complexity gate fired, approved): `docs/plans/<DATETIME>_issue-<NN>_<TITLE>/` with the same `00-index.md` + `NN-<subtitle>.md` structure

Constraints agreed with the user:

- **Only the `docs/issues/NN.md` pattern is supported.** No canonicalization beyond `NN` matching that directory; if no matching issue file exists, the infix is not applied.
- Plans unrelated to any issue keep the existing pattern unchanged.

## Settled decisions

| # | Topic | Decision |
|---|-------|----------|
| Q1 | Trigger | Apply the infix only when the user's plan request references a `docs/issues/NN.md` issue; no globbing for "may relate to" issues. |
| Q2 | Supported pattern | Only `docs/issues/NN.md` (numeric). No other issue-tracker patterns are recognized. |
| Q3 | Naming | `docs/plans/<DATETIME>_issue-<NN>_<fitted_name>.md` for single-file; same infix inserted before `_<TITLE>` for split directories. |

## Open questions

- How to verify the issue mention: require the `NN.md` file to exist at plan-writing time (recommended), or accept user-stated numbers that don't match a file yet?
- Should the plan header additionally link the issue path explicitly (an `**Issue:** docs/issues/NN.md` line), so discovery works both by filename and by content? (Recommended: yes; low cost.)
- Should `supervised-plan-execution` or the `00-index.md` template surface the issue link too, or is the directory name sufficient?

## Acceptance criteria

- § Plan Save Location in `skills/writing-plans/SKILL.md` documents the issue-linked naming as the primary pattern when an issue is mentioned, without changing behavior for unplanned/unrelated plans.
- The rule is written as an observable predicate ("if `docs/issues/NN.md` is referenced in the request", never "consider").
- edited per issue-26 discipline: RED baseline via a subagent pressure scenario ("user: write a plan to address issue 7") before editing, GREEN after, rationalizations harvested into the skill's rationalization table.
