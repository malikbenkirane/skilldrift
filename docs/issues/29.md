# Port explain-diff-html skill to explain-diff (markdown-in-chat)

Source: user request. Upstream skill: https://gist.githubusercontent.com/geoffreylitt/a29df1b5f9865506e8952488eac3d524/raw/126e7fe9eecaafadfe1ac8bb183d135812b608f2/explain-diff-html.md (geoffreylitt).

## Problem

The upstream `explain-diff-html` skill produces a rich, interactive explanation of a code change as a self-contained HTML file written to disk (dated filename in /tmp). We want the same content quality but as Markdown answered directly in the chat — no file creation.

## Desired behavior

New skill at `skills/explain-diff/SKILL.md` (name `explain-diff`):

1. Same four sections as upstream: Background (deep + narrow), Intuition (essence with toy-data examples and diagrams), Code walkthrough (grouped), Quiz (5 medium-difficulty questions).
2. Output is one Markdown document in the chat response. No files, no HTML deliverable.
3. HTML interactivity (clickable quiz revealing correctness) is approximated with collapsible `<details>/<summary>` blocks: question + multiple-choice options in the summary/readable part, answer and feedback hidden inside the collapsed body.
4. Diagrams: upstream bans ASCII-diagrams and uses HTML; markdown version uses Mermaid instead, reusing a small number of diagram families (UI sketch, system/data-flow diagram with example data). Callouts become blockquote callouts.
5. Style: keep the Martin Kleppmann clarity/flow requirement.

## Settled decisions

| # | Topic | Decision |
|---|-------|----------|
| Q1 | Output medium | Markdown in chat only; file creation explicitly prohibited, including HTML artifacts |
| Q2 | Quiz interactivity | Question text visible as plain Markdown above the block; `<details>` block holds only the collapsed answer + feedback (options stay visible). Never put the question inside `<summary>` — some chat renderers swallow summary content. |
| Q3 | Diagrams | Mermaid (flowchart/sequence), reused families, toy data included |
| Q4 | Attribution | Divergence header crediting geoffreylitt's gist with upstream URL, per repo convention |
| Q5 | Section structure | All four upstream sections (Background, Intuition, Code, Quiz). **No TOC** — deferred to another tool. |
| Q6 | Default diff target | Skill infers from context: the **most recent universal diff** found (stated up front). If no diff found, ask the user. |
| Q7 | Exploration depth | Bounded: read the diff, then the touched files' neighbors and definitions, then stop. No outline-approval gate. |
| Q8 | README attribution | Acknowledgments row with the gist URL as link anchor, label "geoffreylitt/explain-diff-html gist", plus divergence header in the skill. |

## Acceptance criteria

- `skills/explain-diff/SKILL.md` exists with YAML frontmatter (`name: explain-diff`, trigger-style description per repo convention: "Use when...").
- No file creation anywhere in the skill; no HTML deliverable instructions remain.
- README Acknowledgments table gains a row linking the gist, labeled "geoffreylitt/explain-diff-html gist".
