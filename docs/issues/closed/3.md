# Merge executing-plans and subagent-driven-development into unified sequential skill

## Problem

Two overlapping skills with artificial distinction:

- `executing-plans`: Simple sequential execution, no quality gates
- `subagent-driven-development`: Complex subagent dispatching, two-stage review

Users had to choose between simplicity and quality. Wrong tradeoff.

## Constraints

1. **LiteLLM proxy + GLM**: Subagent integration not functional
2. **Workflow preference**: Sequential execution more reliable than parallel subagents
3. **Trust model**: Trust dev with self-review rather than delegate to fresh agents

## Solution

Merge into `complete-plan-execution`:

- One agent, sequential execution
- Two-stage self-review after each task (spec compliance → code quality)
- Keep review gates from subagent-driven-development
- Remove subagent dispatch complexity
- Templates (implementer-prompt, spec-review-prompt, code-quality-reviewer-prompt) become self-review checklists

## Result

4 files:
- `SKILL.md` — unified workflow
- `implementer-prompt.md` — implementation self-guidance
- `spec-review-prompt.md` — spec compliance checklist
- `code-quality-reviewer-prompt.md` — code quality checklist

Simpler, more controlled, same quality.
