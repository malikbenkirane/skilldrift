# writing-plans should size-check plans and split large ones into multi-plan batches

Source: brainstorm + grill-me session (2026-10-03). All decisions Q1–Q16 settled in a grill-me round; nothing left assumed. Residuals listed under "Open questions".

## Problem

`writing-plans` (from obra/superpowers, mirrored at `skills/writing-plans/`) writes one giant `docs/plans/<DATETIME>_<PLAN_NAME>.md` regardless of request size. Plans carry exact code, TDD steps, and commits, so they grow fast and become hard to review.

## Desired behavior

After exploration but before drafting any plan file, the skill runs a **complexity gate**:

1. If the plan stays small → current single-file behavior, unchanged.
2. Otherwise → engage the user in chat, propose a split into multiple sub-plans.
3. Split output is a directory, not one file:
   - `docs/plans/<DATETIME>_<TITLE>/`
   - `00-index.md` written first, reviewed by the user
   - `01-<subtitle>.md`, `02-<subtitle>.md`, … sub-plans written after approval
4. Each sub-plan is written one at a time, never in parallel.

## Open questions (residual)

- **RESOLVED A. Threshold values** (Q2): gate fires at **>600 estimated lines OR >15 numbered tasks**, estimated before writing as worst-case lines-per-task (60-170 for a full TDD task with code, test, and the commit sequence) × total tasks. Values are tunable in the SKILL.md "Complexity Gate" conditional. Chosen from the baseline arithmetic (see "Baseline (RED)"): a 15-task plan floors at ~900 lines even under prettified counting, so both thresholds are redundant safeguards.
- **RESOLVED B. Baseline pressure scenarios**: both run 2026-10-10 via subagent, results in "Baseline (RED)" below.

## Baseline (RED, 2026-10-10)

Two subagent pressure scenarios run against the pre-edit SKILL.md:

- **B1 (multi-subsystem spec + sunk-cost pressure, "we've already started, keep one doc"):** agent still split via the existing Scope Check — but into bare per-subsystem files: no measured gate, no `00-index.md`, no execution order/batches, no decline recording. Sunk-cost framing tempted one-file compliance but the Scope Check held.
- **B2 (oversized single-subsystem spec, hands-off user, "don't ask questions"):** the true baseline gap. Agent estimated **2,500-5,500 lines** for one file and confirmed nothing in the skill stops it: no size gate, no estimate step; the only guard (Scope Check) is dialogue-based, classification-dependent, and "a suggestion" — useless against a user who pre-refused dialogue. Root cause recorded: TDD granularity + No-Placeholders mechanically multiply length; the skill never counts the cost.

Rationalizations harvested (now in the SKILL.md rationalization table): "it's really just 2 tasks", "user asked for a plan, not a split", "we've already started, just keep going", "it's one subsystem, so no gate".

## Verification (GREEN, 2026-10-10)

The same B2 + sunk-cost scenario re-run against the edited SKILL.md: gate fired on both thresholds with explicit arithmetic; output is `docs/plans/<DATETIME>_<TITLE>/` with a compact `00-index.md` (sub-plan list, order + rationale, concurrent-eligible batches, checkboxes), sub-plans written one at a time, decline path records in the index without re-asking, Q5 mid-write rule quoted verbatim. Attempted gate evasions (thin-task laundering, cross-reference shortcuts, silent auto-decline) all blocked — skipping the mandatory estimate is the only real loophole and the conditional's observable predicate prevents it.

## Implementation notes 2026-10-10

Changes in `skills/writing-plans/SKILL.md`: divergence header, "Complexity Gate" conditional (measured predicate; hands-off-user proceeds with the split proposal non-blockingly; decline recorded in plan header `## Complexity` line and in an index stub), "Multi-Plan Split" section (directory layout, compact index template incl. concurrent-eligible batches, one-at-a-time authoring, Q9b tick-commit message format, Q5 mid-write rule, Q10 boundary-change rule), "Rationalization Table", updated "Plan Save Location". No wrapper skill; this repo only (Q1/Q6).

## Acceptance criteria

- Baseline test documented first (RED), then SKILL.md edit (GREEN), verified by subagent pressure scenario.
- Gate fires on the two thresholds, proposes the split in chat, records a decline in the index if the user declines.
- Split produces `docs/plans/<DATETIME>_<TITLE>/` with a reviewed index and `NN-<subtitle>.md` sub-plans written one at a time.
- Index contains sub-plan list, execution order + rationale, concurrent-eligible batches, tickable status; ticks committed separately with the agreed message format.
- SKILL.md references upstream as obra/superpowers and carries the divergence header.
