# grill-me should shape questions for scannability (borrowing i-have-adhd techniques)

Source: brainstorm (2026-10-14). Decisions settled in discussion; baseline test still to run (Iron Law) before any edit.

## Problem

`skills/grill-me/SKILL.md` (in `~/.config/crush/skills/grill-me/`, mirrored here) prescribes a frontier/rounds design-tree interview but says almost nothing about **how each question is formed**. Observed failure shapes: compound questions bundling multiple decisions ("should we use jj, and who reviews, and…"), decision frame buried after or under the choices, rounds dumping more questions than the user can hold, and closing summaries written as prose walls instead of scannable legends.

The `i-have-adhd` skill (github.com/ayghri/i-have-adhd, `skills/i-have-adhd/SKILL.md`) contains output-shaping techniques that map well onto question formulation, in a different domain; not everything transfers.

## Desired behavior

Rewrite the question-formatting portions of `skills/grill-me/SKILL.md` so that rounds and questions are shaped for a user with limited working memory, while keeping the frontier/rounds/design-tree model intact. The skill must remain **harness-agnostic**: no dependency on Crush's native `question` tool; rounds stay portable markdown.

Per-question and per-round shape:

1. **One bounded decision per question.** No compound questions; a question containing a second "and…" splits into its own frontier entry (naturally served by the rounds model).
2. **Frame before choices.** State the decision context first, then the answer choices with the recommendation; never bury the frame after the options.
3. **Cap of ~5.** No more than 5 questions per round and ~5 choices per question; the rest of the frontier is retained internally and served in subsequent rounds — the cap shapes presentation only, never analysis or completeness.
4. **Restate state each round.** Each round opens with a one-line recap: what is now settled, what the current frontier is.
5. **Closing legend.** When the frontier empties, the shared-understanding summary is a scannable legend — 2–5 bullets per branch of the design tree — not a prose wall.
